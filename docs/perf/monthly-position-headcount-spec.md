# 每月門市職位人數統計：白話規格

位置：員工管理頁（`/admin/employee-management`）的「每月人數統計」分頁。**唯讀，不修改任何資料。**

## 1. 看得到的人

和員工管理頁相同：admin、營業部助理、營業部主管（職稱為督導／店長／代理店長／督導(代理店長) 者除外）。
判斷寫在 `lib/monthly-staff/employee-management-access.ts`，頁面與 API（`GET /api/admin/position-headcount`）共用同一個函式，
API 端在伺服器上也會檢查（未登入 401、無權限 403），不是只靠畫面。看得到的人看全部門市。

## 2. 版面

- 選月份 →「當月明細」：最上面「全公司合計」，下面依督導區分組，每區先顯示小計，再列各門市。
- 「近 12 個月趨勢」：全公司（每人只算一次）、以所選月份為結尾的 12 個月，每月各欄人數。
- 點任一數字跳出名單（員編、姓名、門市、職位、階段、月狀態、備註）。「其他／兼職」名單上方會列出職位分布。
- 「匯出 Excel」：兩個工作表「人數統計」「人員明細」（人員明細含不計入的人與原因）。
- 畫面有一句說明：各門市、督導區加總可能大於全公司合計（跨店的人在每間門市各出現一次）。
- 手機寬度：表格可橫向捲動，第一欄（門市）固定。

欄位：行政（過階）、行政（未過階）｜新人未過階、新人一階、新人二階、專員、組長、主任、副店長、代理店長、店長、督導｜其他／兼職、階段未登記。

## 3. 誰算「月底在職」（monthly_status 對照表）

資料庫允許的 10 個狀態（另含舊別名 `leave_without_pay`）：

| 狀態值 | 中文 | 是否計入 |
|---|---|---|
| full_month | 整月在職 | 計入 |
| new_hire | 到職（本月新進） | 計入 |
| transferred_in | 調入 | 計入（算在新門市） |
| promoted | 升職 | 計入 |
| leave_return | 留停復職 | 計入 |
| dual_store_manager | 擔任雙店長 | 計入 |
| resigned | 離職 | 不計入 |
| leave_of_absence | 留停 | 不計入 |
| leave_without_pay | 留職停薪（舊別名） | 不計入 |
| transferred_out | 調出 | 不計入（不算在原門市） |
| support_rotation | 支援卡班 | 不計入（不算在被支援門市，原門市另有一筆） |
| 其他（空白或不認得） | 狀態待確認 | **照常計入**，並在畫面上方提示「有 N 筆狀態待確認」，可看名單 |

DEV 目前實際出現的值：full_month、new_hire、transferred_in、transferred_out、resigned；
職位：專員、主任、行政、組長、店長、兼職助理、副店長、新人；新人/行政階段：未過階新人、一階新人、二階新人、過階行政、（空白）。

## 4. 欄位歸類規則

- 行政：階段「過階行政」→ 行政（過階）；「未過階行政」→ 行政（未過階）；空白或看不懂 → 階段未登記。
- 新人：「未過階新人／一階新人／二階新人」；空白或看不懂 → 階段未登記（不猜測，另列名單）。
- 專員、組長、店長：同名欄位。
- 主任、副店長：該月 `is_acting_manager=true` → 只算「代理店長」，不再算主任/副店長。職位本身是「代理店長」→ 代理店長。
- 督導：算「督導」。督導 + `is_acting_manager=true`，或職位「督導(代理店長)」→ 仍算督導，
  並在代理店長欄下方標註「其中 N 位由督導代理」（這些人不加進代理店長人數）。
- 職位帶「-雙」後綴（例：店長-雙）先移除再歸類。
- 其他任何職位（兼職助理、兼職藥師、資深專員、空白…）→「其他／兼職」，不猜測，點開可看實際職位。

## 5. 去重規則

- 門市：同一人在同一門市、同一欄只算一次。
- 督導區小計：同一人在同一督導區、同一欄只算一次。
- 全公司合計：每人只算一次，取一個「主要歸屬」：
  1. 非雙店長／非雙職的那筆優先（`is_dual_position`、狀態 dual_store_manager、職位帶「-雙」者視為雙）；
  2. 職等較高的欄位優先（督導 > 店長 > 代理店長 > 副店長 > 主任 > 組長 > 專員 > 新人二階 > 一階 > 未過階 > 行政過階 > 行政未過階 > 其他 > 階段未登記）；
  3. 門市代號較小者（確保結果固定）。
- 各門市明細照實際登記顯示，跨店的人標「跨店」。所以門市加總可能大於全公司合計。
- 沒有員編的資料以「門市＋姓名」辨識。

## 6. 督導區定義（沿用舊版既有做法）

沿用 `app/api/stores-with-supervisors/route.ts`（績效管理頁「督導區」下拉所用）的認定方式，邏輯已原樣抽成
`lib/stores/supervisor-assignment.ts` 共用（該 API 改為呼叫它，行為不變）：

- 來源是「經理/督導管理」`store_managers`。有 `role_type=supervisor` 者，職稱含「督導」、管理 3 間以上、且未達全部門市 90%（區域經理）才算督導；
- 若沒有任何人符合，改用門市數推斷（無 role_type 標記、管理 3 間以上且未達 90%）；
- 每間門市取第一位符合的督導作為其督導區。沒有督導的門市（含已停用門市）歸「未分區」，排在最後。

## 7. 月份是否定稿（S12）

舊版以 `monthly_store_summary.store_status = 'confirmed'`（店長送出後，由有「確認」權限者按確認；見 `app/store/actions.ts` 的 `confirmStoreStatus`）視為定稿。
所選月份中，有人員資料但門市摘要不是 confirmed（或沒有摘要）的門市算「未定稿」。有任何未定稿門市時，頁面上方顯示
「本月資料尚未定稿，數字可能變動」並列出未定稿門市。仍照常顯示統計。

## 8. 效能

一次批次查詢：門市、督導關聯、該月份人員狀態（趨勢則 12 個月）、門市摘要，共 4 次資料表查詢，人員狀態分頁每頁 1000 筆（沿用 `fetchAllPages` 作法），
不會每間門市各查一次。DEV 整合測試以 1100 筆驗證分頁。
