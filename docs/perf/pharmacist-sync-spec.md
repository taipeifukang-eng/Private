# 藥師主檔與督導區總覽漏同步：修正規格

使用者於 2026-11-06 透過問卷 survey/pharmacist-sync 確認，全部採用建議選項。

## 問題
目前只有在「上次同步之後，有新登錄（created_at）的異動」時才會重新整理。下列兩種情況因此永遠不會被補上：
- 提前登錄的異動：同步當時生效日還沒到。
- 事後修改過的異動。

已發生的實例：FK1299 胡士凡。10/30 02:11 UTC 登錄入職藥師，生效日 11/02；10/30 11:44 UTC 同步一次後，就沒有再同步過。

## 修正
1. **重新整理的觸發條件（three_triggers）：** 未關帳時，上次同步之後只要有符合原類型與範圍的異動，且滿足下列任一條件，就重新整理：
   - (a) created_at > last_synced_at
   - (b) updated_at > last_synced_at
   - (c) movement_date 落在「上次同步的台灣日期」（不含）到「今天」（含）之間
2. **套用範圍：**
   - app/api/pharmacist-annual-master/sync/route.ts（年度主檔）
   - app/admin/pharmacist-management/page.tsx 的每月藥師快照（督導區總覽）。快照的月份範圍與門市範圍照原規則。
3. **同步時間標示：** 畫面上的「已自動同步人事異動（日期）」改成顯示真正最後同步的時間，例如「最後同步：YYYY-MM-DD HH:mm」，以台灣時間顯示。回傳 sync_log 的 last_synced_at，不再回傳 now()。
4. **不變的規則：** 已關帳年度照舊不同步；同步內容與規則本身（syncAnnualMaster 等）不變。
5. **FK1299：** 修正上線後，下次開啟就會自動補上（wait_fix），正式區不需要執行任何指令。
6. **稽核：** docs/perf/audit_pharmacist_master_2026.sql 是唯讀查詢，交給使用者在正式區執行，用來找出其他漏掉的人。

## 測試
三種情況都要有測試，同步之後必須被補上：
- 提前登錄、生效日之後才開頁
- 事後把「是否藥師」修改為是
- 提前登錄的離職

另外要測試：沒有變動時仍跳過同步（不拖慢頁面）。

## 補充（審查後）
- **一次性缺口：** 舊程式的「今天」是 UTC 日期。若某年度主檔是在台灣 00:00-08:00 同步的，當天生效的異動會被漏掉；新觸發條件要求 movement_date 大於上次同步的台灣日期，這類紀錄上線後也不會自動補。請用稽核 SQL 找出這些人，再對該年 sync_log 做一次補正（刪除該年的 sync_log 列，下次開頁即完整重跑）。
- **last_synced_at 取開始時間：** 在讀取異動之前取得，同步進行中才登錄或修改的異動下次仍會被觸發。
- **觸發查詢出錯時降級：** 視為需要同步並記錄 console.error，不讓頁面 500。正式區上線前仍建議唯讀確認 employee_movement_history 有 updated_at 欄位。
- **月快照 notes：** 重算時同一異動的備註片段不再重複附加。月快照的 (c) 條件雖不必要（月快照本就套用整月異動）但無害，保留。
- **稽核 SQL：** 今天改用台灣日期；B 段與 syncAnnualMaster 同優先序（同日 復職 > 留停 > 離職）。
