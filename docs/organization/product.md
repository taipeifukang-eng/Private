# 年度行事曆產品定義

## 產品承諾

讓同仁能快速看懂公司年度安排、個人行程與政府公告假日；授權人員可以直接維護公司行事，變更立即生效，並能查明是誰做了變更。

## 使用者與情境

- 一般同仁：查閱公司行事與政府公告假日，管理自己的行程。
- 個人行事建立者：新增只供自己查看的行程；可選擇分享給指定對象。
- 公司行事管理者：依 RBAC 權限新增或編輯公司會議、活動及重要事項。
- 系統管理者：維護權限與政府公告假日資料來源。

## 核心任務

1. 按年度檢視公司每月安排，能快速辨識日期、活動名稱與活動類型。
2. 查詢台灣政府公告的國定假日及補假日，並與公司行事清楚區分。
3. 建立、檢視及管理個人行程；個人行程預設只有建立者可見，可指定分享對象。
4. 有權限者新增或修改公司行事。新增與修改完成後立即生效，不經待審核流程。
5. 查閱公司行事的異動紀錄，至少能辨識異動者；系統亦應保存異動時間及異動前後日期，方便追溯。
6. 公司行事及已發布的政府假日可單向同步至指定的富康公司 Google 日曆；系統是唯一編輯來源。

## 已確認的產品規則

- 公司行事包含會議、活動、重要事項等安排。
- 公司行事全公司可見；新增與編輯權限仍以 RBAC 控制。
- 公司行事的新增及日期修改由具備相應 RBAC 權限者執行，儲存後立即生效。
- 公司行事的日期修改不走日曆管理者核准流程。
- 公司行事支援全天或指定起訖時間，並可記錄地點；未提供時間的既有行事維持全天。
- Google 同步只寫入伺服器設定的公司日曆 ID；公司行事新增、修改或取消，以及政府假日發布後，更新同一筆 Google 行事或移除已取消／過期的對照行事。
- Google 同步為單向；Google 端的修改不回寫系統。個人行程及其分享資料絕不送入公司 Google 日曆。
- Google 連線憑證只能由伺服器端讀取，使用加密後的 refresh token；同步失敗需可見並能手動重試，不能讓失敗的 Google 呼叫回報成系統行事儲存失敗。
- 公司行事異動需留下執行者。依最新決策，修改原因不列為必填；若日後恢復原因欄位，需另外確認可見範圍。
- 個人行程預設私人；建立時或建立後，都可將單筆行程分享給指定對象。
- 個人行程分享為唯讀；收到分享的人可以再分享給其他系統使用者，建立者可以取消分享。
- 分享權限以登入者身分授予，不產生公開連結。撤回上游分享時，其下游轉分享權限一併失效。
- 政府公告假日是參考資料層，不可直接當作公司已核定的休假或營業日政策。
- 不建立「待核准改期」狀態或相關操作流程。

## 建議的資訊架構

- 日曆檢視：年度／月份瀏覽，按日期查看當日安排。
- 行事來源：公司行事、個人行程、政府公告假日分層呈現，可辨識來源與類型。
- 行程詳情：顯示名稱、日期、類型、建立／異動者及必要的分享資訊。
- 異動紀錄：公司行事修改後保留異動者、時間、修改前後日期；一般檢視者只看到其有權查看的紀錄。
- 手機版：以按日期分組的行程清單為主要瀏覽方式，避免縮小桌面年曆造成難以閱讀。

## 設計概念

年度行事曆採「公司年度排程表」的操作隱喻：月份格線協助定位日期，全年清單用於掃描整年安排，所選日期側欄集中呈現當日細節與操作。公司行事、個人行程、政府公告假日以文字來源與簡潔色彩標示，不把資料做成等權重儀表板卡片。

曾評估的兩種局部呈現：

- 紙本年度月曆：日期辨識最快，但行程密集時名稱容易被截斷，手機上難以使用。
- 月格線搭配日期明細與全年清單：保留熟悉的日期定位，也提供不擠壓文字的掃描方式；選用此方案作為目前操作模型。

## 權限邊界

候選權限需分別涵蓋：

- 查看公司行事。
- 新增公司行事。
- 修改公司行事（立即生效）。
- 管理政府假日資料。
- 管理個人行程及指定分享對象。

以上是產品能力分類，不是已定稿的 RBAC 權限代碼。個人行程的讀取與分享對象限制必須由後端權限政策保護，不能只靠前端隱藏。

## 現有系統整合邊界

- 組織管理已有 `organization_units`、`organization_memberships`、`organization_manager_assignments`，新功能沿用既有組織資料與 `organization.*` RBAC 檢查，不另建一套部門主檔。
- 現有 `event_dates` 是舊式特殊日期資料：日期欄位有唯一限制，不能在同一天記錄多個活動；既有 API 也使用舊 `profiles.role` 判斷寫入權限。它不作為新年度行事曆的主資料來源。
- 既有「活動管理」主要處理業績活動檔期與門市排程，與公司年度會議／個人行程／政府假日分開維護，避免混用權限與作業流程。
- 個人行程具隱私性；不能直接照搬目前組織資料 API 的寬鬆資料存取方式，需以建立者與明確分享對象為資料授權邊界。

## 非功能需求

- 所有日期以台灣時區（Asia/Taipei）呈現與判定。
- 政府假日資料應標示年度、來源、匯入／更新時間；若官方資料更新，能辨識資料版本或更新狀態。
- 政府公告日曆須標示為政府機關辦公日曆參考，不推定私人企業的休假安排。
- 建立、修改、分享及權限拒絕等操作需有清楚的成功、失敗及無資料狀態。
- 未授權使用者不得透過直接呼叫 API 讀取私人行程或修改公司行事。

## MVP 範圍假設

- 公司行事與個人行程可使用全天或指定起訖時間，並可填地點；時間均以 Asia/Taipei 傳給 Google Calendar。
- 首次連結時補同步既有有效公司行事與目前發布的政府假日；往後系統變更立即更新 Google，同步失敗可重試。
- Google 同步只涵蓋公司行事與政府假日，不同步個人行程，不提供 Google 到系統的回寫。
- 第一版不發送新增或改期通知。
- 政府假日由具備管理權限者匯入年度官方 CSV；系統解析後先預覽核對再發布，保留官方來源與版本，不直接假設 CSV 等同公司休假規則。

## 絕不可發生

- 未授權者新增或修改公司行事。
- 修改公司行事後仍要求另一位管理者核准，或讓畫面保留不清楚的待核准狀態。
- 私人行程被其他使用者看見，除非建立者明確分享給對方。
- 將政府公告假日誤呈現為公司已核定的休假日。
- 只用顏色區分公司、個人與政府行事，造成色覺或低彩度顯示時無法辨認。
- 在年度檢視中塞入過多長文，導致日期與行程名稱無法快速掃讀。

## 驗收條件

- 有新增權限的使用者可建立公司行事，儲存後立即出現在有權查看者的日曆中。
- 全公司登入者可查看公司行事；只有具備相應 RBAC 權限者可新增或修改。
- 具 Google 同步管理權限者可連結指定公司 Google 日曆並執行補同步；系統新增、修改、取消及政府假日更新能反映至該 Google 日曆。
- Google 同步維持單向；個人行程永不出現在公司 Google 日曆。既有全天資料維持全天，指定時間與地點依台灣時區同步。
- 有修改權限的使用者可直接改期；不出現審核步驟，且可查到異動者、時間及修改前後日期。
- 無相應權限的使用者無法新增或修改公司行事，包含直接呼叫後端 API 的情況。
- 個人行程建立後預設只有建立者可讀；分享對象唯讀且可轉分享，建立者撤回分享後該分享分支立即失效。
- 政府公告假日與公司行事能從來源標示上清楚區分。
- 月份與年度瀏覽在桌面及手機上均能辨識日期、行程名稱與來源；窄螢幕使用日期清單而非不可讀的縮小表格。

## 實作狀態

產品定義、日曆 UI、時間／地點欄位及 Google 單向同步程式已接入。Google OAuth 用戶端、日曆 ID、加密金鑰及 RBAC 權限仍須在環境與正式資料庫完成設定；首次同步及 Google 帳號授權需部署後實測。政府假日支援一鍵載入人事總處一般版 CSV；解析後先預覽日期、假日類型與來源版本，再以資料庫交易發布並保留舊版本。資料庫 migration 須依序執行基礎行事曆 migration 與 Google 同步 migration，再匯入經核對的政府公告資料。
