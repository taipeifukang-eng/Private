# 年度行事曆架構草案

本文件記錄年度行事曆第一版的實作架構與資料邊界。

## 與現有系統的接點

- 導覽與頁面歸在組織管理；部門範圍可引用既有 `organization_units`。
- 公司行事全公司可見，因此 MVP 不加部門／門市範圍欄位；全公司登入者可讀，新增與修改仍由 RBAC 限制。
- API 沿用 Next.js Route Handler、登入者檢查與 `hasAnyPermission`；不可用 `profiles.role` 或角色名稱代替 RBAC。
- 公司行事的新增與修改採即時生效，不建核准或待核准狀態。
- 舊 `event_dates` 不承載新功能：它限制同一天一筆，也沒有個人擁有者、分享清單與完整異動稽核。
- 個人行程須有獨立的資料存取控制；不能因公司行事可見就讓使用者讀取其他人的私人行程。

## 建議的資料分層

### 公司行事

候選資料表：`organization_calendar_events`

- `id`, `title`, `event_type`（會議／活動／重要事項）
- `start_date`, `end_date`, `description`
- `status`（有效／取消；不包含待核准）
- `created_by`, `updated_by`, `created_at`, `updated_at`

候選異動表：`organization_calendar_event_audit`

- 關聯行事、操作類型、操作者、時間
- 保存異動前後資料，至少包含日期；不接受前端直接指定操作者
- 由資料庫 trigger 或受控 RPC 與行事修改放在同一交易，避免行事已改但稽核未寫入
- 稽核資料不提供一般使用者更新或刪除

### 個人行程

候選資料表：`organization_personal_calendar_events`

- `id`, `owner_id`, `title`, `start_date`, `end_date`, `description`, timestamps
- 預設只有 `owner_id` 可讀寫

候選分享表：`organization_personal_calendar_event_shares`

- `event_id`, `shared_with_user_id`, `shared_by_user_id`, `parent_share_id`, `created_at`, `revoked_at`, `revoked_by`
- 分享權限固定唯讀；建立者新增行程時或事後都可指定分享對象。
- 收到分享的登入者可再分享給其他系統使用者；不建立公開連結。
- 分享紀錄需保留授權來源鏈。撤回某一分享後，該分享及其所有下游分享立即失效；建立者可檢視並撤回整個分享分支。
- 收到分享者可撤回自己建立的下游分享。保留撤回紀錄，不硬刪除分享歷程。
- 後端資料政策檢查建立者或分享鏈上所有上游授權均有效；不能只在 UI 篩選。

### 政府公告假日

候選資料表：`organization_calendar_holiday_imports` 與 `organization_calendar_holidays`

- 匯入批次保存年度、官方來源連結、版本／公告資訊、匯入者與匯入時間。
- 日期資料保存日期、名稱及類型，至少區分國定假日與補行上班日。
- 匯入修正版時保留來源與版本資訊，避免靜默覆寫後無法追查。
- 顯示名稱需明確標示為政府機關辦公日曆參考，不代表公司休假政策。

## 權限草案

以下僅為權限拆分建議，正式代碼需在 migration 前確認。公司行事檢視對所有登入者開放，不另設檢視門檻：

- `organization.calendar.company.view`
- `organization.calendar.company.create`
- `organization.calendar.company.edit`
- `organization.calendar.holiday.manage`

個人行程原則上由登入者管理自己的資料，不需要管理全公司的個人行程權限；指定分享對象取得該筆行程唯讀權限，並可向其他登入者再分享。

## 主要操作流程

### 公司行事

1. 使用者開啟年度行事曆，系統依有效權限載入公司行事與政府假日。
2. 有新增權限者建立行事；儲存後立即顯示給該行事可見範圍內的人員。
3. 有編輯權限者直接修改日期或內容；交易同時保存操作者與前後值，成功後立即更新檢視。
4. 無編輯權限者只檢視，不顯示可操作控制項；API 與資料庫政策仍須拒絕未授權寫入。

### 個人行程

1. 建立後預設私人。
2. 建立者可在新增時或事後指定分享對象；分享者可再轉分享給其他登入者。
3. 所有分享對象都只能查看；建立者或分享鏈中的分享者可撤回自己授予的分享。
4. 撤回分享後，該授權分支及其下游分享立即失效；只允許建立者與仍在有效分享鏈上的人讀取行程。

### 政府公告假日

1. 管理者匯入指定年度官方資料並保存來源與版本資訊。
2. 使用者可在日曆顯示／隱藏政府參考層；不把政府假日自動轉成公司休假設定。

## 建議 MVP 順序

1. 公司行事與異動稽核：先完成 RBAC、資料存取政策、即時新增／改期。
2. 政府假日參考層：年度資料匯入、來源標示與版本記錄。
3. 個人行程與指定分享：最後加入，因為需要最嚴謹的個人資料授權與分享邊界。

## MVP 假設

- 公司行事以日期／日期區間為單位，暫不記錄開始與結束時間。
- 第一版不發新增或改期通知。
- 政府假日由管理者一鍵載入人事總處一般版 CSV，或上傳已下載的 CSV；解析後預覽日期與分類，再發布版本，保留人工核對及來源追溯。

## 實作狀態

- `20261008100000_organization_annual_calendar.sql` 已建立，含公司行事、異動稽核、個人行程分享鏈、政府假日版本及原子發布函式；尚未在任何資料庫執行。
- API 已接上登入者、RBAC、RLS；個人行程分享採唯讀且可沿有效授權鏈轉分享。
- 日曆頁已接入組織管理導覽，提供月格線、全年清單、日期明細、公司／個人行事表單及政府假日年度匯入表單。
- 假日匯入先從人事總處資料頁尋找所選年度一般版 CSV，再回退查詢政府資料開放平台的官方資料集（可取得歷年檔案），或由管理者上傳 CSV；拒絕 Google 專用版，解析整年日期後先預覽再發布。
- CSV 使用既有 `xlsx` 解析器，檢查年度天數、重複日期、公告旗標；按備註辨識國定假日／補假，按非上班週末辨識補行上班。
- 尚未完成真實資料庫 migration 執行、已登入角色端到端測試及官方假日資料匯入驗證。
