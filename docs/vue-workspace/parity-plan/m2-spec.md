# M2 人事：最終規格

使用者於 2026-11-05 透過問卷 survey/m2 確認，送出時間 2026-11-05 14:43 UTC。範圍：W05 員工管理與員編、W06 人事異動與升遷、P02 門市／店長／督導／員工匯入對等驗收。

凡與舊版行為不同的項目，parity allowlist 一律寫 `approvedBy: "user (2026-11-05 survey/m2)"` 並註明題號。

## A. 異動回寫每月人員名冊（核心）

- **A.1 回寫範圍（monthly_sync_scope）：** 入職、升職、代理、留職停薪、復職、過試用期、離職、調店，全部自動更新「生效日所在月份，以及之後所有已初始化的月份」。尚未初始化的月份，初始化時依異動紀錄一次算好。先初始化後登錄，和先登錄後初始化，結果必須相同。
- **A.2 已送審或已確認的月份（monthly_locked）：**
  - 異動照常登記，草稿月份自動更新。
  - 已送審或已確認的月份不動，產生「需重新確認」清單，在月結頁顯示受影響的門市、月份、員工與原因。
  - 月份退回草稿後，可一鍵依異動重算。
  - 新版調店目前的 WORKSPACE_MONTH_LOCKED 整筆拒絕，改成這套規則。
- **A.3 店長手動改過的資料（manual_overwrite）：** 以異動為準覆蓋，被改的欄位留下記號，月結頁顯示「近期因異動自動調整」清單（誰、哪個欄位、原值到新值、哪筆異動）。不發 LINE。
- **A.4 留職停薪（leave_months = drop_during_leave，與舊版不同）：**
  - 留停當月：仍列名冊，狀態「留停」，天數為留停日前一天。
  - 留停期間的後續月份：不列名冊。
  - 復職當月起：列入「復職門市」的名冊，天數從復職日（含）起算。
  - 使用者補充：**復職不一定回原店**，復職異動必須能指定門市；未指定時預設原店。
- **A.5 月中調店（transfer_mid_month）：** 天數規則照舊（調出店天數為調店日前一天，調入店從調店日起算，含當天）。兩家店的該員工列都加提示「請填寫本店實際時數」，兼職尤其需要。
- **A.6 升職的生效月份：** 從升職日所在月份起，整月認定新職位。代理店長只標註記，不改正式職位。

## B. 職等與「目前職位」

- **B.1 補登過去的異動（backdate_rule = history_only）：** 所有類型都允許補登，只寫歷史；員工目前狀態以最新一筆為準，月份名冊依生效日重新計算。新版調店目前的 WORKSPACE_LATER_MOVEMENT 拒絕，改成這套規則。
- **B.2 同時登記多階升職（使用者補充）：** 例如同時登記新人一階與新人二階，或新人二階與專員。這種情況下，員工的目前職位與該月份名冊職位，要呈現**相對最高的職等**。
  - 判斷順序：生效日較晚者優先；生效日相同時，取職等最高者。
  - 門市職等由低到高：新人（未過階）、新人（一階）、新人（二階）、專員、組長、主任、副店長、店長、督導、經理。代理店長只是註記。
  - 門市行政職等由低到高：行政（未過階）、行政（過階）。
  - 共用一份職等表（建議放在 lib/workspace/position-rank.ts），施作時要對照系統實際的職位與階段值，對不上的回報給使用者，不要自行猜測。
- **B.3 升職要同步員工主檔（使用者回報的問題）：** 曾經發生「升職異動已改到月度資料，員工管理的職位卻沒改」。升職、代理、過試用期等異動，必須同時更新員工主檔的目前職位與階段，並依 B.1、B.2 的規則決定。
  - 施作時要先查清楚舊版漏改的原因，並寫測試。
  - 另外產出一支唯讀檢查 SQL，列出「主檔職位和最新升職異動不一致」的員工，交給使用者在正式區執行，不要自動修正。

## C. 修改與刪除歷史異動

- **C.1 刪除後恢復（history_delete_restore = restore_latest_only）：**
  - 只能刪除該員工最新的一筆異動。如果有更晚的異動，提示先刪較新的那一筆。
  - 刪除後自動恢復員工主檔的狀態、門市、職位，以及受影響月份的名冊，月份範圍套用 A.1 和 A.2。
  - 修改的範圍照舊版：可改姓名、日期、備註、升職的職位與階段、入職的藥師身分；不開放改類型與門市。修改後一樣做 A 組的連動。
- **C.2 權限（history_permission = legacy_perms）：**
  - 修改：有「異動管理」、「員工管理」、「批次升遷」任一權限即可。
  - 刪除：要有「刪除異動」權限。
  - 有批次升遷權限的人也看得到歷史頁。
  - 一律走 workspace API，在伺服器端檢查權限。

## D. 調店與批次處理

- **D.1 批次原子（batch_atomic = atomic_skip_dup，核可 D08）：** 員工匯入、異動批次、批次升遷都是整批成功或整批不存。完全重複、已存在的列自動略過並在結果中列出；其他錯誤整批不存，預覽逐列說明原因。
- **D.2 調店確認（direct_transfer_bypass = both_supervisors，與舊版不同）：**
  - 調店不論是用申請，還是用批次輸入登記，都要**原店督導與新店督導都確認**才生效。
  - 兩店是同一位督導時，確認一次即可。
  - 系統管理員可以代為確認，並留下紀錄。
  - 批次輸入的調店列會建立成待確認的調店申請，不會直接生效。
  - 確認畫面要顯示兩位督導各自的確認狀態。
- **D.3 批次升遷核對（promotion_strict = strict）：** 員編和姓名都必須相符、員編必須是該店員工、擋重複、擋已停止的門市。維持新版做法。

## E. 員編規則與員工主檔

- **E.1 員編格式（code_rule = all_strict）：**
  - 合法格式只有三種：FK+4 碼數字、FKF+5 碼數字、FKPT+3 碼數字。
  - 所有新增入口都強制：新增員工、異動入職、員工匯入、每月人員狀態手動新增、生日匯入（只比對既有員編）。
  - 共用 lib/workspace/employee-id-rule.ts。
  - 輸入時去掉前後空白並轉大寫。
  - 只擋新建立的員編，既有員編不改，編輯時員編唯讀。
- **E.2 實習生（fki = forbid）：** 移除 FKI 格式，所有入口都不允許。使用者決定：**實習生不出現在系統裡**。如果舊版每月人員狀態有「實習生不填員編」之類的新增方式，施作時先回報使用者，不要自行刪除或保留。
- **E.3 兼職判斷（fkpt_type = auto_pt）：** FKPT 開頭的員編自動設為兼職，其餘為正職。新增畫面要顯示「類型：兼職（依員編）」。
- **E.4 在員工管理改職位（edit_position = unlocked_only，與舊版不同）：** 姓名全部月份同步；職位只改尚未送審、尚未確認的月份。已送審或已確認的月份不動，列進 A.2 的需重新確認清單。

## F. 門市、督導、匯入

- **F.1 匯入職位（import_position = restrict）：** 員工匯入的職位欄必須在公司職位清單內，否則預覽時標示錯誤。
- **F.2 督導主責（supervisor_primary = explicit）：** 維持新版，有多位督導的門市必須明確指定主責；與舊版不同。
- **F.3 地圖與提示（map_and_extras = recommended）：**
  - 地圖預設只顯示營運中的門市，有「查看已停止門市」權限的人可以勾選顯示。
  - 補回門市列表的「已停止數量」，以及店長指派頁的「已有店長」提示。
  - 督導統計卡不補。
- **F.4 其餘：** P02 共 11 頁照舊版做逐頁對等。新版已有的增強維持不變，包括友善錯誤訊息、版本衝突防護、停用前確認、已停止門市不能搬遷、一起成功或一起不做。

## G. 預設做法（問卷附錄，使用者未提異議）

- 異動類型共 8 種，必填欄位與日期規則照現況：日期格式為西元 YYYY-MM-DD，1912 年起，過去與未來都可以填。
- Excel 員編欄只有 4 位數字時自動補 FK，只有 5 位數字時補 FKF。
- 新增員工時的重複員編檢查：員工主檔、每月人員狀態、異動紀錄，任何一處已有就擋。
- 不新增停用或刪除員工的功能，離職一律走人事異動。
- 日期檢查沿用新版：生日不可晚於今天，也不可晚於到職日；日期不早於 1900 年。
- 天數規則：離職當天算上班，留停前一天為最後工作日，復職含當天。
- 月初以前已離職的人不帶入新月份名冊。
- 員工匯入上限 10,000 列、5MB，要有 employee.import 權限，只能匯入營運中且看得到的門市。
- 測試資料只放在 VW、ZT 測試門市，以及保留月份 2099-xx；sweeper 檢查結果必須是 0 筆孤兒資料。
