# 請款單紙本格式列印（ga-pr-print）正式區 SQL 草稿

**這些是草稿，沒有在正式區執行過。** 內容與 DEV 實測檔（`supabase/workspace-dev/20261126110000_ga_pr_print_fields.sql` 與 `.rollback.sql`）完全相同，單元測試 `tests/unit/GAPRINT/sql-files.test.ts` 逐檔比對。DEV 已做過「套用 → 撤回 → 再套用」往返。

## 這份 SQL 做了什麼（白話）

老闆要求請款單列印改成和紙本表單一樣的格式。紙本上有幾個欄位系統原本沒有存：**申請部門、申請人、檢附單據、申請事由**。這份 SQL 只做三件事：

1. 在請款單資料表加 4 個「可以是空的」新欄位（`applicant_name`、`applicant_dept`、`attach_docs`、`reason_override`）。舊的請款單這四格都是空的，空的就代表「列印時用系統預設值」（申請人與部門帶建立人、檢附單據水電寫「繳費單」採購寫「發票」、申請事由自動組）。
2. 新增一支「儲存列印欄位」的函式 `ga_ws_pay_request_print_fields_set`：
   - 需要「請款管理」權限（和修改請款單同一個權限），沒有權限會被擋下。
   - 除了「已作廢」的請款單，草稿、已送出、已付款都能改。改的只是列印字樣，**不會動金額、狀態、廠商、銀行資料，也不會改請款單的版本時間**（所以不會害別人正在編輯的草稿出現「剛被修改」的衝突）。
   - 只有內容真的有變動才會寫一筆「update」操作紀錄，記錄改了哪幾個欄位。
3. 新增一支「列印補充資料」的唯讀函式 `ga_ws_pay_request_print_extra`：回傳建立人的姓名與部門、水電請款單每張帳單的門市簡稱與帳單備註。需要「請款檢視」權限；帳單備註另外需要水電檢視權限，沒有就不回。

**沒有改任何既有函式**（請款單查詢、修改、動作函式都沒動），**沒有新增權限碼、沒有授權給任何角色**，沒有新資料表。

## 先決條件

1. 第 4.5 批請款單、水電話費請款（G46，`ga_payment_request_bill_lines`）、ga-improve-b1 已在正式區（腳本開頭會檢查，缺少就中止、不會改任何東西）。
2. 這份 SQL 建議在程式上線**之前**先執行（程式讀不到新函式時會退回「只用請款單上的欄位」，不會壞，但門市簡稱與帳單備註會缺）。

## 套用順序

1. （可選）執行前先把 `ga_payment_requests` 的資料筆數記下來。
2. 執行 `01-ga-pr-print-fields.sql`（可以重複執行）。
3. 執行 `01-ga-pr-print-fields.verify.sql`，每一列都要是 `pass`。
4. 登入後開一張請款單，確認「列印欄位」區塊可以儲存、「列印請款單」是紙本格式。

## 撤回

執行 `01-ga-pr-print-fields.rollback.sql`。**如果已經有請款單填了這四個欄位，撤回會中止**（避免資料被丟掉），要先確認那些內容可以捨棄。撤回後執行 verify 應該會出現 `fail`（代表已經撤回）。

## 風險

低。只加可為空的欄位與兩支新函式，不碰既有資料與既有函式。長度限制（申請人、申請部門 50 字，檢附單據 100 字，申請事由 200 字）是新欄位自己的限制，舊資料不受影響。
