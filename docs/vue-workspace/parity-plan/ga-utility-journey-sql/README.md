## 01 付款日到期自動變已付款（01-ga-auto-pay-due）

### 做了什麼（白話）

老闆要求：請款單到了付款日，系統自己把它標成「已付款」，不用總務每天手動點。水電請款單與採購請款單都適用。

1. **付款日怎麼算**
   - 請款單上有填「預計付款日」，就用它。
   - 沒填的時候：水電請款單用「這張單所含帳單裡最早的繳費期限」；採購請款單沒有預計付款日就**不處理**（不會亂標）。
2. **只處理「已送出」的單**。草稿、已付款、已作廢都不動。
3. **每天台北時間凌晨 00:05** 自動跑一次（用資料庫的 pg_cron 排程，排程名稱 `ga-auto-pay-due-requests`）。跑的是 `ga_apply_due_payment_requests()`，可以重複執行，已經標過的不會再標。每張單各自處理，某一張出問題只會略過那一張，不會讓整批失敗。
4. **標成已付款時寫什麼**
   - 付款日期＝那張單的「付款日」（不是排程實際執行的那天，所以晚一天才跑也是記原本的付款日）。
   - 付款方式：單上已經有就用，沒有就記「轉帳」。
   - 付款人是空的（系統標記，沒有人）；新增一個 `paid_auto` 欄位記下「這是系統自動標的」。
   - 操作紀錄多一筆「標記已付款」，原因寫「付款日到期，系統自動標記已付款」，內容帶 `auto = true`，畫面上操作者顯示「系統」。
5. **取消自動付款**（新功能，需要「請款管理」權限）
   - 只限「系統自動標記」的已付款單；人工標記的已付款單不能用（標錯請作廢後重開）。
   - 要填取消原因。取消後這張單改回「已送出」，付款日期、付款時間、付款人都清掉，操作紀錄多一筆「取消自動付款」。
   - **取消後這張單不會再被系統自動標記**（資料庫記一個 `auto_pay_off`）。要付款時請用原本的「標記已付款」手動處理。這個做法比「要求同時改預計付款日」簡單，也不會有「取消完隔天又被標回去」的情況。畫面上的取消對話框有說明這件事。
6. 總務仍然可以在付款日前手動標記已付款。水電帳單「已繳費」的規則完全沒有改。

### 資料庫上動了哪些東西

- 請款單資料表新增 2 個欄位：`paid_auto`、`auto_pay_off`（都是「是／否」，預設「否」，所以舊資料不受影響）。
- 「已付款必填」檢查放寬一點：自動標記的單可以沒有付款人，其他情況照舊都要有。
- 操作紀錄類型多一個 `cancel_auto_pay`（舊的類型都保留）。
- 請款單狀態守門（`ga_pay_request_guard`）多兩個**只在同一個交易內有效的旗標例外**：只有「排程函式」與「取消自動付款函式」會設旗標，其他任何寫入方式都不能改自動付款標記，也不能讓已付款的單變回已送出。其餘規則（作廢鎖定、金額與廠商鎖定、已付款資訊鎖定、狀態轉換表）一個字都沒改。
- 新函式 3 支：`ga_pay_auto_pay_date`（算付款日，不對外）、`ga_apply_due_payment_requests`（排程用，**只開放給系統帳號 service_role**，匿名與一般登入者都不能呼叫）、`ga_ws_pay_request_cancel_auto_pay`（取消用，登入者可呼叫，函式內檢查請款管理權限）。
- 新增 1 個排程（pg_cron）。
- **沒有新增權限碼、沒有授權給任何角色、沒有新資料表、沒有改任何既有函式內容**（除了上面說的狀態守門）。

### 先決條件

1. 第 4.5 批請款單、水電話費請款（`ga_payment_request_bill_lines`）、ga-improve-b1（買受人、同仁代墊、預付款）已在正式區。腳本開頭會檢查，缺少就中止，不會改任何東西。
2. 正式區已安裝 pg_cron（升遷生效排程 `workspace-promotion-activation` 已在用）。沒有 pg_cron 的環境，腳本只會丟一個提示、不建排程，這種情況要自己用其他方式每天呼叫 `ga_apply_due_payment_requests()`。
3. 建議在**程式上線之前**先執行。程式沒更新時，畫面看不到「系統自動標記」與「取消自動付款」，但排程仍會跑；程式上線後才會看到標記。

### 套用順序

1. （可選）先記下請款單 `SUBMITTED` 的張數，以及其中有預計付款日、而且日期已經過去的有幾張——**這些單在第一次排程跑的時候會被一次標成已付款**（付款日已過期的送出單都算「到期」）。如果不希望這樣，上線前先請總務處理掉，或把那些單的付款日調整。
2. 執行 `01-ga-auto-pay-due.sql`（可以重複執行）。
3. 執行 `01-ga-auto-pay-due.verify.sql`，每一列都要是 `pass`（沒有 pg_cron 的環境排程那一列是 `skip`）。
4. 隔天早上確認：開一張「已送出、付款日已到」的請款單，狀態變成已付款並顯示「系統自動標記（付款日 …）」。

### 撤回

執行 `01-ga-auto-pay-due.rollback.sql`。**如果已經有系統自動標記的已付款單、已取消自動付款的單，或操作紀錄裡已有「取消自動付款」，撤回會中止**（避免資料或稽核紀錄被丟掉）。撤回會移除排程、三支函式、兩個欄位，並把狀態守門與檢查條件還原成原本的樣子。撤回後再執行 verify 應該會出現 `fail`（代表已經撤回）。

### 風險

- **中低**。最需要留意的是上面「套用順序」第 1 點：上線第一天，過期未處理的已送出單會一次被標成已付款。
- 狀態守門函式被換成新版（多兩個旗標例外），其他請款單操作完全不受影響；DEV 的請款單整套 e2e（建立、送出、退回、標記已付款、作廢、預付款、水電）都有跑過。
- 付款日是「預計付款日」，所以預計付款日填錯（例如填成過去）會讓單子被提早標成已付款；送出後預計付款日就鎖定不能改，填錯要退回草稿修改。
