# 水電話費請款（G46）正式區 SQL 草稿

> 狀態：草稿，**尚未套用到正式區**。老闆 2026-11-24 問卷已定案（U1 至 U8），設計見 `../ga-utility-payment-design.md`。
> 上線時間：**12/8 全面切換之後**（約 12/15 那週）；本資料夾**不併入 12/8 當晚的 SQL 步驟頁**。
> 所有檔案都已在 DEV 實測：套用、撤回、再套用；撤回後 9 支被加掛的函式定義與撤回前逐字相同。05 補填腳本與撤回也在 DEV 實跑過（補填、再補填不重複、被有效請款單占用時撤回被擋、作廢後撤回乾淨）；02 另含「直接寫入防護」，水電管理者直接改資料表也不能偽造自動標記、不能指向非公用事業或已停用的廠商。

## 這批做什麼（白話）

請款單多一種「來源」：採購，或水電話費。水電話費請款單付給「公用事業」繳費單位（台電、台水、電信公司），一張單只含同一個繳費單位、同一個帳單月份；
送出前每張帳單要有附件；送出後帳單可自動標已繳，請款單退回或作廢時只把「這張請款單自動標的」改回待繳。採購請款完全不動：水電明細放在獨立的新資料表，對既有函式只做「來源是水電才分流」的最小加掛。

每個檔案（00 除外）都有 `.rollback.sql`（撤回）與 `.verify.sql`（**只有 SELECT**，每列一個檢查項目，status 是 pass 或 fail）。全部可重複執行（已套用的略過）。
**不含任何 GRANT 給角色、不新增權限碼**：誰能用，由老闆在上線時另外決定（見下方建議授權名單）。

## 套用步驟（正式區）

1. 確認 12/8 全面切換已完成並穩定、老闆同意排上線日。
2. 執行 `00-preview-before-apply.sql`，**整份輸出存檔**。要求：
   - A 區沒有 MISSING（第 4.5 批草稿 50 至 61、第 6 批 G23〔45〕與廠商〔44、48〕都已套用且驗收通過）。
   - D 區每一列 `SHAPE_MISMATCH` 都不能有（有就代表正式區現行函式和 DEV 實測版本不同，**停止，先回報**）。
   - B 區：看「金額有小數」的筆數。很少就請總務先修成整數；很多就先回報，要不要改成「請款時四捨五入、差額記備註」另議。
   - C 區：看是否已有「公用事業」分類（有就直接沿用，01 不會重複新增）。
3. **備份**：`ga_utility_bills`、`ga_payment_requests`、`ga_workflow_settings`、`ga_service_categories` 四張表的資料，以及 E 區輸出的 9 支函式全文。
4. 依序執行並各自驗證：`01` → `01.verify` → `02` → `02.verify` → `03` → `03.verify` → `04` → `04.verify`（verify 全部 pass 才進下一步；任何一步出錯，用該步的 `.rollback.sql` 撤回，再往前一步依序撤回）。
5. **黃金快照等價查詢**：套用前後各查一次採購請款的列表、金額彙總（例如各狀態張數與總額、各採購單累計請款），數字必須相同。
6. 總務在廠商資料新增台電、台水、中華電信等廠商並勾「公用事業」分類（統編必填）；再用畫面「補填繳費單位」（或核可後跑 `05`）為既有帳單補填繳費單位。**補填前，帳單不能請款**。
7. **驗收**：用一張小額真實帳單或標記清楚的測試帳單走完：建立 → 缺附件被擋 → 補附件送出 → 退回 → 作廢，確認帳單狀態跟著回復，再清除測試資料。
8. **老闆決定角色授權**（本批不授權）。

## 撤回順序

`04` → `03` → `02` → `01`（05 若有跑，最先撤回 05）。`01` 的撤回有安全規則：若已有「非作廢的水電請款單」或「由請款單自動標記已繳的帳單」，開頭就中止並列出筆數，請先把這些請款單作廢、確認帳單狀態後再撤回。
撤回 `02`、`04` 依 `GAUP-BEGIN／GAUP-END` 標記移除加掛文字（不整支覆蓋），DEV 實測撤回後函式定義與撤回前逐字相同。

## 建議授權名單（只列不授權）

| 對象 | 建議給的權限碼 | 能做什麼 |
|---|---|---|
| 總務（負責建立、送出水電請款單） | `utility_bill.manage`＋`utility_bill.view`、`purchase_payment.manage`＋`purchase_payment.view`、`vendor.view` | 建立、修改草稿、送出、補填繳費單位、上傳帳單附件 |
| 會計 | `purchase_payment.manage`＋`purchase_payment.view`、`utility_bill.view`、`vendor.view` | 退回、作廢、標已付款；看得到明細、統編與銀行（**不需要**水電管理，帳單回復由資料庫同步情境放行） |
| 只看請款單的人 | `purchase_payment.view` | 看單頭與總額，明細顯示「已遮蔽」 |
| 店長 | 不給 | 看不到入口、頁面與 API |

規則重點：建立、修改、送出需要「請款管理」**加**「水電網費管理」（缺一不可）；退回、作廢、標已付款只要「請款管理」；請款單明細另需「水電帳單檢視」；廠商統編與銀行另需「廠商檢視／管理」。
應用層 `profiles.role = admin` 不放行請款入口與請款寫入，資料庫沒有管理員繞過（正式區 `has_permission` 語意）。

## 已知行為（給老闆看的白話）

- 「待付款」徽章、首頁待辦、「草稿逾 14 天」會把水電請款單算進去（它們本來就是「請款單」口徑）；沒有水電請款單時數字與現在完全相同。
- 勾「送出後帳單自動標記已繳」：繳費日期＝送出當天（台北日期）；不套「帳單月份前 1 個月」的限制。會計標已付款不影響帳單。
- 作廢「已付款」的水電請款單：帳單會改回待繳（畫面會先提醒「款項已付，請確認是否需要追回」）。
- 帳單金額有小數或為 0：不能請款，要先到水電帳單修正。
- 水電對帳 CSV 預設仍是採購；要匯水電要在匯出時選「水電話費」（兩邊欄位不同，分開匯出）。
- 公用事業廠商不從採購單廠商下拉隱藏（不動採購單行為）。
