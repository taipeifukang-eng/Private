## 演練目的

## 演練內容（每個裝置各跑一次）

1. 管理員逐頁檢查「回舊版」連結（網址正確、另開分頁、手機沒有水平溢出、點擊區夠大；沒有舊版對應的頁面不顯示）。
2. 店長開著新版「商品部」（缺貨回報）。
3. 管理員到「角色權限管理 > 頁面回舊版設定」把商品部切回舊版（必填原因；沒填會被擋）。
4. 店長開選單：商品部改開舊版 `/cross-dept/merchandise`（另開分頁）；原本開著的新版頁籤顯示通知與舊版連結。
5. 管理員改回新版；店長選單的商品部恢復開新版，頁籤通知消失。
6. 稽核：資料庫留下「切回舊版」「改回新版」各一筆（誰、何時、原因）。
7. 還原演練（整合測試）：執行 rollback SQL 後 session 照常運作、全部視為開新版，再套用後恢復。

## 生效時間與快取（明確）

- 伺服端：`/api/workspace/session` 每次請求都直接讀資料庫（`force-dynamic`，`Cache-Control: no-store`），**沒有任何伺服端快取**。管理員儲存成功後，下一個 session 請求就會看到新狀態（整合測試逐一驗證）。
- 前端：每 60 秒、視窗取得焦點、開啟選單時重新讀取 session。因此使用者最慢 60 秒內生效（開選單時通常立即生效，見上表耗時）。
- 備援表不存在或讀取失敗：視為沒有任何頁面切回舊版，不讓工作台壞掉。

## 上線當天實際操作步驟（給系統管理員）

1. 登入工作台 > 選單「角色權限管理」> 右上角「頁面回舊版設定」。
2. 找到有問題的頁面，填寫原因，按「切回舊版」。最慢一分鐘內所有人的選單就會改開舊版。
3. 問題修好後，同一頁按「改回新版」。
4. 想看是誰、什麼時候、為什麼切換：同一頁每一列下方會顯示最後一次修改的人、時間與原因。
