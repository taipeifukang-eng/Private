### 套用順序與注意

1. 先執行 `00-readiness-check.sql`、`11-g01-preview-before-apply.sql`、`12-g02-disabled-categories-with-active-items.sql` 與 `13-g03-parts-stock-and-duplicates.sql`（都是唯讀）。
2. 沒有 MISSING 後，執行 `10-g01-catalog-rules.sql`，核對函式清單（檔案內已自動 COMMIT，不用另外執行）。
3. 新版第 1 批不需要補 `maintenance-photos`（工單照片）、QR 觸發器（第 2 批）。
4. 附件新規則（照片縮小、4MB 上限、刪除只標記）全在應用程式，不需要改正式區儲存空間設定（儲存空間單檔上限仍是 20MB，比 4MB 寬，沒有衝突）。

## 上線部署清單（不是 SQL，是主機與設定）

只列已確定要在上線當天做的設定與驗證；之後各批次會繼續往下加。

1. **QR 標籤網址的網域（Q9，使用者 2026-11-09 確認）**：標籤上的網址不再取瀏覽器目前網址，改由伺服端環境變數 `NEXT_PUBLIC_SITE_URL`（專案既有的網站網址設定，忘記密碼信也用它）決定。
   - 到 Vercel 正式環境設定 `NEXT_PUBLIC_SITE_URL` 為**正式網站網址**（例如 `https://正式網域`，不加結尾斜線、不含路徑）。測試區用測試區自己的網址（DEV 已設定）。
   - 正式建置缺少這個變數、或格式不是 `http(s)://網域`，標籤列印會直接報錯並擋下，不會退回用瀏覽器網址。
   - 非正式環境（不是 Vercel 的 production）印出的標籤會加「測試」浮水印，避免測試標籤被貼到實體設備上。
   - **用舊標籤實掃驗證**：設定完成後，拿一張已貼在設備上的舊標籤，用手機實際掃描，確認會到正式網站、能登入後看到那台設備；再印一張新標籤掃一次，確認網址網域與舊標籤相同。永久網址 `/general-affairs/assets/scan/{token}` 的 token 一律沿用，不會重發。
2. **轉移單、貼標需要店長名單**：貼標待辦用 `store_managers` 名單內任何身分判斷；轉移單的確認交出、確認收到只認 `role_type = store_manager`。上線前用 `20` 的第 6 區看「沒有店長名單身分的門市」，補齊後再開放轉移單。
3. **上線貼標流程的順序**：套用 `21` → `22` → `23` → 部署新版程式 → 總務用 Excel 匯入各店設備與設施 → 依門市印標籤（單次上限 300 張）→ 店長手機逐台上傳照片與貼標照 → 總務複核 → 看「上線貼標進度」頁到各店 100%。
4. **QR 永久網址轉到新版掃描頁的旗標（G10，使用者驗收後才打開）**：環境變數 `WORKSPACE_SCAN_REDIRECT` 預設不設（舊版掃描頁行為完全不變）。驗收通過、`NEXT_PUBLIC_SITE_URL` 也設好之後，再把它設為 `true`，重新部署。打開後，手機掃舊標籤（網址 `/general-affairs/assets/scan/{token}` 不變）會轉到新版掃描頁；未登入會先登入、登入後回到同一台設備。
   - 打開當天用一張已貼在設備上的舊標籤實掃：(1) 已登入手機掃，看到該設備；(2) 登出後再掃，先登入再回到同一台設備；(3) 掃一張已報廢設備的舊標籤，看到「這個 QR Code 已作廢」的說明；(4) 店長掃別間門市設備，看到白話說明與該門市店長姓名。
   - 發現問題要立刻回復：把 `WORKSPACE_SCAN_REDIRECT` 改回空白或刪除並重新部署，舊版頁面即恢復，標籤不用重印。
5. **Excel 匯入的使用提醒（Q29）**：總務在「Excel 匯入」頁下載範本填寫（只收 .xlsx、2MB、500 列；超過請分檔）。系統會先逐列預檢，只要有一列有錯整批都不會寫入，改好重傳即可；同一個檔案連按兩次不會重複新增。匯入不需要額外的主機設定，也不會動到舊版畫面。設備沒填購置日期就不會自動產生資產編號（標籤列印時會警告，之後補編號即可）。
