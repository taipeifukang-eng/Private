# 新版工作台上線檢查表（老闆版）

給：老闆（不需要會寫程式）。
這份是「上線當天照著做」的清單。環境變數怎麼設，請看同一個資料夾的 `vercel-env.md`，這裡不重複，只在需要的地方告訴你去看哪一節。

## 先看這 6 句話

1. 你已決定的事：新版和舊版放在同一個網站（網址後面多 `/workspace/`）、共用舊版登入、先只開放管理員、之後再全面開放、舊版選單直接連到新版頁面、每一頁都能單獨切回舊版。
2. 程式合併進 `main` 的那一刻，新版是**關閉**的。沒有設任何新變數，舊版完全照舊。所以合併本身不會影響任何人。
3. 真正「開門」的動作只有兩個：把 `WORKSPACE_ENABLED` 設成 `true`（管理員先用），以及把 `WORKSPACE_AUDIENCE` 改成 `all`（所有人）。兩個都要 **Redeploy** 才生效。
4. 出事了，把 `WORKSPACE_ENABLED` 改成 `false` 再 Redeploy，或用 Vercel 的即時回復，新版就關了。
5. 這次一起上線的還有兩批資料庫指令：水電話費請款（G46）和採購請款改善（B1）。照你的決定，它們和這次部署**一起上**，不是之後另外再排日期。
6. 每一步都有「誰做、做完看到什麼才算過」。沒看到該看到的，就停下來，不要往下一步。

## 四、上線日 步驟 3：管理員試用（新版只對管理員開放）

1. 到 Vercel：Settings > Environment Variables，新增 `WORKSPACE_ENABLED`，值填 `true`，**只勾 Production**，Save。
2. 確認 `WORKSPACE_AUDIENCE` 還是 `admin_only`。
3. 到 Deployments，找最上面 Ready 的 Production 部署，按右邊「…」選 **Redeploy**，確認，等到 **Ready**。
4. 工程跑正式區的唯讀冒煙檢查，用「管理員」的登入 Cookie：

   `node scripts/workspace-prod-smoke.cjs --base-url https://正式網域`

   應該全部通過。
5. 再用「非管理員」的登入 Cookie 跑一次，加上參數 `--expect-open=false`：

   `node scripts/workspace-prod-smoke.cjs --base-url https://正式網域 --expect-open=false`

   應該全部通過，代表非管理員看到的是「新版尚未開放」。
6. 你自己用管理員帳號登入，確認：
   - 舊版選單出現新版的連結，點下去直接進新版頁面。
   - 新版畫面上方有「目前僅管理員可用」的橫幅。
7. 找一個非管理員（例如一般店長）帳號登入：舊版選單**不會**出現新版連結；若直接輸入新版網址，會看到「新版尚未開放」和「前往舊版首頁」連結。

**應該看到**：管理員能用新版，其他人完全沒被打擾。

## 五、步驟 4：管理員試用期

- 由你（和你指定的管理員）實際使用新版，試用期間多久由你決定，請寫在最後的簽核表。
- 重點試這些：請款流程、水電話費請款、採購請款、盤點、各角色該有的功能。

- 試用期內，舊版繼續是所有人在用的主要系統，資料兩邊共用。

## 六、步驟 5：全面開放（決定 D10：試用後隔天早上）

1. 到 Vercel：Settings > Environment Variables，找 `WORKSPACE_AUDIENCE`，Edit，值改成 `all`（Production），Save。
2. Deployments > 最上面 Ready 的 Production 部署 > 「…」> **Redeploy** > 確認，等到 **Ready**。
3. 工程再跑一次冒煙檢查：先用管理員 Cookie（預設即可），再用一個一般店長 Cookie，兩個都應該通過，而且一般店長現在也看得到新版（不再是「尚未開放」）。
4. 開店前請總務或你自己抽查一家店的店長帳號，確認選單和新版頁面都正常。

**應該看到**：有權限的人都能用新版；沒有權限的人看到的是原本的無權限提示。

## 七、緊急關閉

### 做法 A：關掉開關（約 1 到 2 分鐘）

1. Vercel：Settings > Environment Variables，找 `WORKSPACE_ENABLED`，Edit，改成 `false`（或直接 Remove），Save。
2. Deployments > 最上面 Ready 的 Production 部署 > 「…」> **Redeploy**，等到 **Ready**。
3. 結果：舊版選單只剩舊版連結，沒有新版按鈕；新版的 API 一律回「新版暫時關閉」；舊版功能照常。

### 做法 B：Vercel 即時回復（最快）

1. Deployments 找到「上一個正常的 Production 部署」。
2. 按右邊「…」，選 **Instant Rollback**（或 **Promote to Production**）。
3. 這是直接換回舊部署，不用重建。注意：這會連程式碼一起退回。

### 資料庫的撤回

資料庫指令的撤回請用操作頁每一步的「撤回」說明，順序是**後做的先撤**（先 B1，再 G46）。關掉新版**不會**自動撤回資料庫指令，兩件事要分開想：關新版只是讓畫面回到舊版。

## 八、單頁切回舊版（不是全站關閉）

如果只有某一頁有問題，不需要關整個新版：

1. 管理員登入新版，打開「**頁面回舊版設定**」管理頁。
2. 找到有問題的那一頁，打開開關，並**填寫原因**（沒填原因不能切）。
3. 約 **60 秒內**生效：使用者再點選單，會連到舊版的那一頁。已經開著新版那一頁的人，會看到通知和舊版連結。
4. 問題解決後，在同一頁把開關關掉，就回到新版。

要注意：
- 這是「導覽用」的切換，只是把連結換回舊版，**不是安全控制**。真的有安全或資料風險，請用第七節的緊急關閉。
- 水電話費請款（G46）和採購請款改善（B1）的新頁面如果也想要單頁回舊版，需要工程先在設定表加上對應的列，請事先告知。
