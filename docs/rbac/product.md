# 角色權限管理產品定義

最後更新：2026-09-27

## 產品承諾

讓系統管理員用業務能力而非資料庫代碼配置角色，並在儲存前清楚知道新增、移除及高風險權限。

## 使用者與情境

| 使用者 | 情境 | 核心需求 |
|---|---|---|
| 系統管理員 | 建立或調整公司角色 | 快速給予合理的查看範圍與日常操作 |
| 權限維運人員 | 查核異常或修正誤授權 | 看懂實際能力、技術代碼及異動內容 |

## 核心任務

1. 依模組與功能找到要設定的能力。
2. 優先選擇安全的查看或日常處理權限。
3. 必要時逐項開啟刪除、強制結案、撤銷等進階權限。
4. 儲存前檢查本次新增與移除內容。
5. 遇到其他管理者已更新時重新載入，不覆蓋較新的設定。

## 介面原則

- 每個功能先回答「看得到哪些資料」及「可以做哪些事情」。
- 技術權限碼是查核資訊，不應成為一般操作的主要視覺內容。
- 批次設定不得默默帶入刪除、強制結案、撤銷或取消確認。
- 畫面只能有一個主要儲存入口，且只在有異動時出現。
- 模組、功能與個別權限的層級必須可辨識，但避免重複摘要與控制。

## 系統狀態

- 載入中、無查看權限、無分配權限、無搜尋結果。
- 尚未儲存、儲存中、儲存成功、儲存失敗。
- 並行更新衝突與重新載入。
- 高風險權限開啟確認。

## 絕不能發生

1. 「查看」被誤解或擴張成查看全部資料。
2. 一般批次操作同時授予刪除或強制結案。
3. 使用者離開頁面時無提示地遺失尚未儲存的變更。
4. 兩位管理者的更新互相靜默覆蓋。
5. 同一畫面出現多個意義相同的主要儲存按鈕。

## 驗收準則

- [ ] 管理員能在 3 秒內找到目前角色已開啟的模組。
- [ ] 一般授權不需要理解英文權限代碼。
- [ ] 日常處理不包含高風險權限。
- [ ] 高風險權限只能逐項明確開啟並確認。
- [ ] 儲存前可看見新增與移除的權限摘要。
- [ ] 並行更新不會覆蓋其他管理者的新設定。
